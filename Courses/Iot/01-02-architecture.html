1.2 — IoT Architecture

⏱ 25 min read 📖 Theory 🎯 Beginner 🧩 Module 01 · Lesson 2

Every IoT system — from a smart bulb to a smart city — is built on the same four-layer architecture. Understanding this blueprint is the single most important mental model you'll carry through the rest of this course.

💡 What you'll learn

The 4 layers of IoT architecture, what lives in each layer, and how data flows between them.

Why an architecture matters

When you build your first IoT project, it's tempting to jump straight to code. But without understanding the layers, you'll hit walls fast:

  • You won't know where to process data (device vs cloud)
  • You'll pick the wrong protocol for your use case
  • You'll struggle to scale from 1 device to 1,000
  • You'll miss critical security gaps between layers

The 4-layer model solves all of this by giving every piece a clear home.

The 4 layers of IoT

🖥️

1. Application Layer

The user-facing part — dashboards, mobile apps, alerts, APIs. This is where humans interact with the system and where business logic lives.

☁️

2. Processing Layer

Also called the middleware or cloud layer. Stores data, runs analytics, applies rules, and decides what actions to trigger.

📡

3. Network Layer

Moves data from devices to the cloud and back. Includes Wi-Fi, cellular, LoRaWAN, BLE, and protocols like MQTT, HTTP, and CoAP.

🌡️

4. Perception Layer

Also called the sensing layer. Physical sensors and actuators that interact with the real world — temperature, motion, light, pressure.

Layer 1 — Perception Layer

The bottom of the stack. This is where the physical world becomes data.

What lives here

  • Sensors: Temperature (DHT22), motion (PIR), light (LDR), distance (ultrasonic), gas, humidity, pressure
  • Actuators: Motors, relays, LEDs, buzzers, servo motors, valves
  • Microcontrollers: ESP32, Arduino, Raspberry Pi Pico — the brain that reads sensors and drives actuators
📌 Key idea

This layer doesn't "think" much — it just converts physical signals to digital values (and vice versa).

Layer 2 — Network Layer

The transport system. It gets data from the device to wherever it needs to go.

What lives here

  • Wireless: Wi-Fi, Bluetooth Low Energy (BLE), Zigbee, LoRaWAN, NB-IoT, 4G/5G
  • Wired: Ethernet, RS-485, Modbus (common in factories)
  • Protocols: MQTT (pub/sub), HTTP/REST, CoAP, WebSockets
  • Gateways: Devices that bridge local networks to the internet
✅ Rule of thumb

Pick your network based on range, power, and bandwidth. Short-range + low-power → BLE. Long-range + low-power → LoRaWAN. High-bandwidth + always-on → Wi-Fi.

Layer 3 — Processing Layer

The brain. This is where raw data becomes useful information.

What lives here

  • Cloud platforms: AWS IoT Core, Azure IoT Hub, Google Cloud IoT
  • Databases: Time-series (InfluxDB, TimescaleDB), NoSQL (MongoDB), SQL
  • Stream processing: Apache Kafka, AWS Kinesis, Node-RED
  • Rules engines: "If temperature > 40°C, send alert"
  • Edge computing: Processing near the device instead of the cloud (faster, cheaper, works offline)
⚠ Edge vs Cloud

Cloud = unlimited power, but latency and cost. Edge = fast and cheap, but limited compute. Real systems use both.

Layer 4 — Application Layer

The top. Where humans actually see and use the system.

What lives here

  • Dashboards: Grafana, Node-RED Dashboard, custom React/Vue apps
  • Mobile apps: iOS/Android apps that control devices
  • Alerts: Email, SMS, push notifications, Slack
  • APIs: REST/GraphQL endpoints for third-party integrations
  • Business logic: Billing, user management, reporting

How data flows: a full example

Let's trace a smart greenhouse through all four layers:

  1. Perception: A DHT22 sensor reads 38°C and 45% humidity
  2. Network: The ESP32 publishes this as an MQTT message to greenhouse/zone1/temp
  3. Processing: A rule on the cloud checks: "Is temp > 35°C?" → Yes → trigger cooling
  4. Application: A dashboard lights up red, an SMS is sent to the farmer, and a fan command is published back
  5. Network: The command greenhouse/zone1/fan=ON travels back over MQTT
  6. Perception: The ESP32 receives the command and drives a relay to turn on the fan
🔄 Notice

Data flows up (sense → cloud) and commands flow down (cloud → actuator). Both directions matter.

Common alternative models

You'll see other breakdowns of IoT architecture. They're variations of the same idea:

  • 3-layer model: Perception, Network, Application (processing is folded into application)
  • 5-layer model: Adds a "Business Layer" on top for business models and analytics
  • 7-layer model (IoTWF): Cisco's extended model for enterprise IoT

For learning and building, the 4-layer model is the sweet spot.

Key Takeaways

  • Every IoT system has 4 layers: Perception, Network, Processing, Application
  • Perception = sensors + actuators + microcontrollers (the physical world)
  • Network = how data travels (Wi-Fi, MQTT, LoRaWAN)
  • Processing = where data is stored, analyzed, and acted upon (cloud or edge)
  • Application = what humans interact with (dashboards, apps, alerts)
  • Data flows up; commands flow down
  • When designing a project, sketch all 4 layers before writing code
